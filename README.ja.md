# claude-session-brief

[English](README.md)

[Claude Code](https://claude.com/claude-code) の mod です。prompt のすぐ上に、そのセッションの概要を出します。複数のセッションを並べて操作していても、切り替えた先のセッションが何のためのもので、今どこまで進んでいるかが、会話をさかのぼらずに分かります。

```text
目的: 決済 webhook のハンドラに、バックオフつきの再試行を入れる                 b: 詳細
現状: ローカルのテストは通った。PR を作ってよいか、ユーザーの返事を待っている
```

(Claude Code の `language` を `"Japanese"` にしたときの表示です。)

## 表示する内容

メインの会話 (subagent ではない会話) のターンが終わるたびに、Haiku が概要を書き直します。材料は、前回の概要、そのターンの依頼、Claude の回答、Claude が出した質問とその回答、そのターンにツールで行った操作です。どの行も画面の幅で切らず、折り返して全文を出します。

- **prompt の上の帯**には、目的と現状を出します。ターンの実行中は、前回の現状を出したまま「(作業中)」を付けます。
- **`/brief`** を打つと、概要の 6 項目すべてをセッション概要パネル (題が「セッション概要」のパネル) に出します。下のキー設定を足せば ctrl+x b でも開けます。帯の「詳細」ボタンでも開けます。セッション概要パネルの表示中は、帯と同じ内容をこのパネルが持つので、帯は消えます。

| 項目 | 内容 |
| --- | --- |
| 目的 | 何のためのセッションか。対象 (PR、ファイル、機能) を名指しする |
| 現状 | 今どこまで進んでいるか |
| やったこと | これまでにやったこと。5 件まで |
| 決定事項 | 決まったこと。Claude の質問への回答を含む。5 件まで |
| 確認待ち | Claude が回答や操作を待っていること |
| 次にやること | Claude が次にすること |

最初のターンが始まるまでは、帯を出しません。最初の概要ができるまでは、帯に「(最初のターンの後に表示)」と出します。

概要はセッションごとに保存します。解析済みのセッションを開くと、保存した概要をすぐに出します。まだ解析していないセッションや、保存した後に会話が進んだセッションは、開いた時点で解析します。

## キー操作

`~/.claude/keybindings.json` に次の設定を足すと、ctrl+x を prefix にして概要を操作できます。

| キー | 動作 |
| --- | --- |
| ctrl+x b | 概要の全文をセッション概要パネルで開く。このパネルの表示中なら閉じる |
| ctrl+x i | 帯をたたむ。もう一度押すと戻る |

```json
{
  "bindings": [
    {
      "context": "Chat",
      "bindings": {
        "ctrl+x b": "app:cycleDiffBase",
        "ctrl+x i": "abovePrompt:toggle"
      }
    }
  ]
}
```

mod は独自のキー操作を定義できないので、ctrl+x b には既存の操作を借りています。`app:cycleDiffBase` は差分パネルの比較基準を切り替える操作で、Claude Code がこれを自分で処理するのは差分パネルを開いている間だけです。このため、差分パネルを開いている間の ctrl+x b は、今までどおり比較基準を切り替えます。差分パネルを閉じていれば、この操作で帯の「詳細」ボタンが押され、セッション概要パネルが開きます。セッション概要パネルの表示中にこの操作をすると、このパネルの「閉じる」ボタンが押され、セッション概要パネルが閉じます。`abovePrompt:toggle` は帯をたたむ Claude Code の操作で、既定では ctrl+x ctrl+a に割り当てられています。ctrl+x i は、この操作に 2 つ目のキーを足すだけです。

セッション概要パネルは、「閉じる」ボタン (このパネルにフォーカスがあるときに `b`) や Esc でも閉じられます。キー設定を足さない場合は、`/brief` でセッション概要パネルを開くか、ctrl+x tab で帯にフォーカスしてから `b` を押します。帯は ctrl+x ctrl+a でたためます。

## インストール

```text
/plugin marketplace add skanehira/claude-session-brief
/plugin install session-brief@claude-session-brief
/reload-plugins
```

Claude Code 2.1.287 で動作を確かめています。mod の機能は early access で、その API はリリースごとに変わることがあります。

## 表示の言語

概要は、Claude Code 本体の `language` 設定に従います。`"language": "Japanese"` なら、見出しも日本語になり、Haiku も概要を日本語で書きます。ほかの言語を設定している場合は、見出しは英語のままで、Haiku がその言語で書きます。設定が無ければ、すべて英語です。

## コストと送る内容

メインの会話のターンが終わるたびに、mod は Haiku を 1 回呼びます。呼び出しには、利用中の Claude Code のセッションと同じアカウントとプロバイダを使います。セッションを開いたときは、保存した概要が無いか古い場合に限り、もう 1 回呼びます。送るのは、セッションのうち次の部分だけです。

| 送るもの | 上限 |
| --- | --- |
| 前回の概要 | 6 項目 |
| そのターンの依頼 | 先頭 800 文字 |
| そのターンの Claude の最終回答 | 先頭 3000 文字 |
| そのターンに出した質問と、その回答 | すべて |
| そのターンの操作: シェルコマンド (説明文。説明文が無ければコマンドの 1 行目)、編集・作成したファイル、subagent、skill、Web の取得と検索、MCP ツール | 30 行まで |
| 引き継ぐ概要が無いとき: それまでの依頼 | 直近 20 件、各 120 文字 |
| 引き継ぐ概要が無く、セッションが compact されているとき: compact が残した要約 | 先頭 2000 文字 |

ファイルを読む操作と、ファイルを検索する操作は送りません。subagent のターンと、subagent が呼んだツールも送らず、Haiku の呼び出しのきっかけにもなりません。非対話の実行 (`claude -p`) では呼びません。Haiku から使える返答が無いとき (Haiku を使えないバックエンドなど) は、最終回答のうち見出しでない最初の行を、現状にします。

## 動作の注意点

- **ダイアログの間は帯が隠れる。** ターミナルでは、AskUserQuestion のダイアログと権限確認のダイアログが prompt の領域を置き換え、その間 Claude Code は帯を描きません。セッションが何を待っているかは、ダイアログ自体が示します。
- **セッションは開いた時点で解析する。** `claude --resume`、`claude --continue`、実行中のセッションでの `/resume` のどれでセッションを開いても、mod はその会話を読み直します。最後の依頼より後に書いた概要がストアにあれば、その概要をすぐに出し、Haiku は呼びません。無ければ、その場で履歴から最初の概要を書きます。材料は、それまでの依頼と、compact されたセッションなら compact が残した要約です。mod を入れる前から続いているセッションも、compact した直後でまだターンが無いセッションも、この手順で解析します。compact より前のターンは会話から消えているので、それらの内容は compact の要約からしか分かりません。
- **概要の保存先。** mod 専用のストアで、`~/.claude/plugins/store/` の下の JSON ファイルです。セッション ID ごとに 1 件を持ちます。新しい順に 200 セッション分を残し、それより古いものはセッションの開始時に消します。
- **`/clear` すると最初から。** 新しい会話は、新しいセッション ID で自分の概要を持ちます。
- **Claude Code 専用。** この mod は Claude Code の mod API の上で動きます。Codex、OpenCode などのエージェントはこの API を読み込まないので、それらのセッションには何も出ません。

## うまく動かないとき

**帯が出ない。** 次の順に確かめます。

1. mod が読み込まれているか。`/br` と打って `/brief` が候補に出れば、読み込まれています。出なければ、`/plugin` で session-brief が有効か確かめ、`/reload-plugins` を実行します。設定や組織のポリシーで hooks を無効にしている環境では、mod の hooks も動きません。
2. 依頼を始めたか。帯は最初の依頼から出ます。ダイアログや survey の表示中は、帯は消えます。
3. 帯をたたんでいないか。たたんだ帯は「▸ plugin panel hidden」と表示されます。ctrl+x ctrl+a (上のキー設定を足していれば ctrl+x i) で戻ります。
4. 対話のセッションか。非対話の実行 (`claude -p`) では帯を出しません。

**概要が更新されない。** Claude Code を `claude --debug` で起動し、debug ログから mod の行を探します。

```bash
rg 'session-brief:' ~/.claude/debug/latest
```

`summary failed` は、Haiku の呼び出しそのものが失敗したことを示します。設定で Haiku の使用が許されていない場合などに起きます。

**概要が間違っている。** 概要は前回の概要をもとに書き直すので、誤りが残ることがあります。会話から書き直させるには、次の手順を踏みます。

1. そのセッションを開いている Claude Code のプロセスをすべて終了します。プロセスが動いている間は、そのプロセスが概要を持ち続け、また保存します。
2. ストアから、そのセッションの 1 件を消します。ストアは `~/.claude/plugins/store/` にある、名前が `session-brief_` で始まる JSON ファイルで、mod の読み込み方ごとに 1 つあります。まず、ストアの全件をキーと目的の組で一覧し、目的の文からそのセッションのキーを探します。

   ```bash
   jq -r 'to_entries[] | "\(.key)\t\(.value.sections.purpose // "")"' ~/.claude/plugins/store/session-brief_*.json
   ```

   キーは、`brief:` にセッション ID を続けたものです。セッション ID は、`~/.claude/projects/` の下にあるそのセッションの transcript ファイルの名前から、`.jsonl` を除いたものです。見つけたキーを `key=` の行に貼り、すべてのストアからその 1 件を消します。

   ```bash
   key='<見つけたキー>'
   for f in ~/.claude/plugins/store/session-brief_*.json; do
     jq --arg key "$key" 'del(.[$key])' "$f" > "$f.tmp" && mv "$f.tmp" "$f"
   done
   ```

   すべてのセッションを最初からにするには、ストアのファイルごと消します。
3. `claude --resume` でセッションを開き直します。mod が会話を読み直し、新しい概要を書きます。

## 開発

```bash
claude plugin validate .claude-plugin/plugin.json   # プラグインを検査する。manifest と hooks module を Claude Code と同じ読み方で読む
claude plugin validate .                            # マーケットプレイスの manifest を検査する (hooks module は読まない)
claude plugin test .                                # hooks/*.test.ts(x) を Claude Code の上で動かす
claude --plugin-dir .                               # セッションで試す
tsc -p .                                            # 型を検査する。Claude Code が mod を読み込んだときに書き出す .claude-plugin/types/ が要る
```
