## 要約の生成

`turn.complete` で最終回答を記録し、`$.clock.after(0, ...)` で hook の処理の外に要約を予約します。メインの会話はモデルの返答を待ちません。非対話セッションでは会話の記録もモデル呼び出しも行わず、subagent のターン終了でも要約を生成しません。

システムプロンプトでは、セッションの内容を指示ではなく記録として扱うよう求めます。返答には `purpose`、`status`、`done`、`decisions`、`pending`、`next` を持つ JSON オブジェクトを要求します。解析時には目的と現状が空でないことを確認します。各文字列は 500 文字までに切り詰め、末尾に `…` を付けます。リストは空でない最新 5 件を元の順番で残します。この上限はモデル出力の解析に適用され、代わりの概要には記録した依頼と回答を使います。

メモリ上では、ターンと質問をそれぞれ 50 件まで保持します。依頼を取り出す際には、ユーザーの依頼やプロンプトコマンドを、ツール結果・通知・続行と区別します。`localeFor` は前後の空白を除いた言語設定が `/^(ja\b|japanese|日本語)/i` に一致すると見出しを日本語にし、それ以外は英語にします。概要には設定した言語を使い、設定が無ければ英語にします。

## コストと送る内容

mod は、利用中の Claude Code のセッションを通じて Haiku を呼びます。アカウントとプロバイダもセッションと同じです。1 回の呼び出しは、出力 1000 トークンと 30 秒までです。呼ぶのは次の時点です。

- メインの会話のターンが終わるたび。
- セッションを開いたときと、動いているセッションに mod を初めて読み込んだときや読み直したとき。保存した最新の概要が無く、解析する材料があるときに限ります。

非対話の実行 (`claude -p`) では呼びません。呼び出しを止めるには、mod を無効にします (`/plugin`、または `claude plugin disable recap-plus@claude-recap-plus`)。Haiku を呼ばずに帯だけを出す設定はありません。

送るのは、セッションのうち次の部分だけです。

| 送るもの                                | 送る時点                                                 | 上限                                       |
| --------------------------------------- | -------------------------------------------------------- | ------------------------------------------ |
| 前回の概要                              | 毎回                                                     | 6 項目                                     |
| そのターンの依頼                        | 毎回                                                     | 先頭 800 文字                              |
| そのターンの Claude の最終回答          | 毎回                                                     | 先頭 3000 文字                             |
| そのターンに出した質問と、その回答      | 毎回                                                     | すべて                                     |
| そのターンにツールで行った操作 (下の表) | 毎回                                                     | 直近 30 行、各 160 文字                    |
| それまでの依頼                          | 引き継ぐ概要が無い間だけ                                 | 直近 20 件。各依頼の 1 行目の先頭 120 文字 |
| compact が残した要約                    | 引き継ぐ概要が無い間だけ。compact されたセッションのとき | 先頭 2000 文字                             |

| ツール       | 送る内容                                  |
| ------------ | ----------------------------------------- |
| Bash         | 説明文。説明文が無ければコマンドの 1 行目 |
| Edit、Write  | ファイルのパス                            |
| NotebookEdit | ノートブックのパス                        |
| Agent、Task  | 説明文                                    |
| Skill        | skill の名前                              |
| WebFetch     | URL                                       |
| WebSearch    | 検索語                                    |
| MCP ツール   | ツールの名前だけ                          |

ファイルを読む操作と、ファイルを検索する操作は送りません。上の表に無いほかのツールも送りません。subagent のターンと、subagent が呼んだツールも送らず、Haiku の呼び出しのきっかけにもなりません。

Haiku から使える概要が返らなかったとき (API エラー、空の返答、30 秒の時間切れ、求めた形でない返答) は、mod が代わりの概要を作ります。代わりの概要は、前回の概要の現状だけを、最終回答のうち見出しでない最初の行に置き換えたものです。前回の概要がまだ無いときは、依頼の 1 行目を目的にし、ほかの項目を空にします。この概要も、ほかの概要と同じく保存します。最終回答にそのような行が無ければ、概要は変えません。

## セッションのライフサイクル

### ダイアログの間は帯が隠れる

ターミナルでは、AskUserQuestion のダイアログと権限確認のダイアログが prompt の領域を置き換え、その間 Claude Code は帯を描きません (Claude Code 2.1.287 で確かめました)。セッションが何を待っているかは、ダイアログ自体が示します。Claude Code のアンケート (survey) も同じ場所に出るので、その間も帯は消えます。

### セッションを開いたとき

`claude --resume`、`claude --continue`、実行中のセッションでの `/resume` のどれでセッションを開いても、mod はその会話を読み直します。動いているセッションに mod を初めて読み込んだときも同じです。

- **保存した概要が最新のとき。** 保存した概要が最後のターンより後に書かれたもの、つまり最後のターンの依頼と回答が保存したときと同じなら、その概要をすぐに出し、Haiku は呼びません。
- **最新でないとき。** その場で履歴から概要を書き直します。材料は、それまでの依頼と、compact されたセッションなら compact が残した要約です。書き終わるまで、帯は「(最初のターンの後に表示)」と出します。

mod を入れる前から続いているセッションも、この手順で解析します。compact した直後でまだターンが無いセッションも同じです。この場合は、compact より前に保存した概要を使わず、compact の要約から書き直し、書き終わると帯を出します。compact より前のターンは会話から消えているので、それらの内容は compact の要約からしか分かりません。

### 概要の保存先

mod 専用のストアです。ストアは `~/.claude/plugins/store/` にある、名前が `recap-plus_` で始まる JSON ファイルです。mod の読み込み方ごとに別のファイルになります。たとえば `--plugin-dir` で読み込んだときは `recap-plus_inline-<hash>.json` です。ファイルはセッションごとに 1 件を `recap-plus:<セッション ID>` というキーで持ちます。1 件の中身は、6 項目、最後のターンの依頼と回答から作った指紋、保存した時刻、Haiku の呼び出し回数とトークン数の累計です ([コストと送る内容](#コストと送る内容)を参照)。新しい順に 200 セッション分を残し、それより古いものはセッションの開始時に消します。

### `/clear` すると最初から

新しい会話は、新しいセッション ID で自分の概要を持ち、Haiku の呼び出しを 0 から数えます。

## 帯の表示状態

| 時点                                                       | 帯                                             |
| ---------------------------------------------------------- | ---------------------------------------------- |
| 最初のターンの前                                           | 何も出さない                                   |
| 最初の概要ができるまで                                     | 2 行とも「(最初のターンの後に表示)」           |
| ターンの実行中                                             | 前回の概要。「現状」の後に「(作業中)」を付ける |
| ターンが終わってから Haiku の返答が届くまで (ふつうは数秒) | 前回の概要                                     |
| ダイアログや survey の表示中、セッション概要パネルの表示中 | 何も出さない                                   |

## キー操作の仕組み

mod は独自のキー操作を定義できないので、ctrl+x b には既存の操作を借りています。`app:cycleDiffBase` は差分パネルの比較基準を切り替える操作で、差分パネルの中では既定で ctrl+x b に割り当てられています。Claude Code がこの操作を自分で処理するのは、差分パネルを開いている間だけです。このため、差分パネルを開いている間の ctrl+x b は、これまでどおり比較基準を切り替えます。差分パネルを閉じていれば、この操作で帯の「詳細」ボタンが押され、セッション概要パネルが開きます。セッション概要パネルの表示中にこの操作をすると、このパネルの「閉じる」ボタンが押され、セッション概要パネルが閉じます。`abovePrompt:toggle` は帯をたたむ Claude Code の操作で、既定では ctrl+x ctrl+a に割り当てられています。ctrl+x i は、この操作に 2 つ目のキーを足すだけです。

## 保存項目と更新順序

| 項目・用語     | 生成者                                      | 利用先・意味                                                                          |
| -------------- | ------------------------------------------- | ------------------------------------------------------------------------------------- |
| `sections`     | `parseSections` または `fallbackSections`   | 帯とパネルが表示する 6 項目                                                           |
| `turnKey`      | `turnKeyOf`                                 | `openSession` が最後の依頼と回答を保存済みの指紋と比較する                            |
| `savedAt`      | 保存時の `$.clock.now()`                    | `pruneStore` がセッションを保存時刻順に並べる                                         |
| `usage`        | モデルが返すトークン数を加算する `addUsage` | 呼び出し回数と入力・出力トークン数の累計。古いデータに有効な値が無ければ 0 から数える |
| `epoch`        | clear・resume 時の `startOver`              | 別の会話へ古い返答を反映しないための、メモリ上の世代番号                              |
| `sectionsTurn` | `setSections`                               | 古いターンの概要で新しい概要を上書きしないための、メモリ上のターン番号                |

`turnKey` は記録した依頼、区切りの NUL 文字 (`\u0000`)、回答に FNV-1a を適用し、`v1:<16 進数 8 桁>` にした指紋です。ターン番号は含めないため、compact で番号だけが変わっても保存済みの概要を無効にしません。ストアに保存するのは `sections`、`turnKey`、`savedAt`、`usage` で、メモリ上のターン履歴や `epoch` は保存しません。

古い `epoch` の返答は使用量も含めて破棄します。同じ会話の古いターンの返答が遅れて届いた場合は、概要を上書きせず、使用量だけを加算します。使用量は次に概要を保存するときに書き込むため、その前にプロセスが終了すると保存されません。確認コマンドは[使用量の確認](troubleshooting.md#使用量の確認)を参照してください。

`/clear` や同じプロセス内の `/resume` の後は、新しいセッション ID を 500 ms 間隔で最大 20 回確認します。既に次のターンが始まっている場合は、状態を再構築せず、そのターンに新しい ID を設定します。

## ホスト API の前提

互換性情報は Claude Code 2.1.287 での既存の動作確認に基づきます。ターミナル・デスクトップアプリでの帯の表示、ダイアログ中の非表示、キー操作の処理、ストアのファイル名は、ホスト側の動作に依存します。mod API は early access です。VS Code 拡張とモバイルでは概要パネルだけを使えますが、この 2 つでは動作未検証です。hooks の登録、送信上限、状態管理は、上の表で挙げたソースファイルで定義しています。
