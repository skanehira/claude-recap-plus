# 詳細なトラブルシューティング

- 種別: 診断手順書

[利用ガイド](../README.ja.md#うまく動かないとき)

以下のコマンドには `rg` と `jq` が必要です。

## 概要が更新されない

Claude Code を `claude --debug` で起動し、debug ログから mod の行を探します。

```bash
rg 'recap-plus:' ~/.claude/debug/latest
```

| 行                                                     | 起きたこと                                                                                                                                                                                                                                                                                                                                       | どうするか                                                               |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `recap-plus: Haiku gave no recap-plus: <理由>`         | Haiku の返答に使える概要が無かった。mod は代わりの概要を作るか、最終回答に使える行が無ければ概要を変えなかった ([要約の生成](architecture.md#コストと送る内容)を参照)。理由は `api-error status=<HTTP の状態コード。応答が無ければ null> error=<種類>`、`empty-reply`、`aborted` (打ち切り、または 30 秒の時間切れ)、`unreadable-reply` のどれか | レート制限や過負荷はそのうち収まり、次のターンでまた呼ぶ                 |
| `recap-plus: summary failed: <エラー>`                 | 要約の生成や保存で例外が発生した。Haiku を利用できない場合など                                                                                                                                                                                                                                                                                   | エラーの内容と Haiku の利用可否を確認し、解消しなければ mod を無効にする |
| `recap-plus: /recap-plus was not registered: <エラー>` | `/recap-plus` の登録が拒まれた                                                                                                                                                                                                                                                                                                                   | 帯の「詳細」ボタンか ctrl+x b でセッション概要パネルを開く               |
| `recap-plus: following the session failed: <エラー>`   | `/clear` や `/resume` の後で、mod が新しいセッションを捉えられなかった                                                                                                                                                                                                                                                                           | Claude Code を終了し、`claude --resume` でセッションを開き直す           |

## 概要が間違っている

概要は前回の概要をもとに書き直すので、誤りが残ることがあります。会話から書き直させるには、次の手順を踏みます。

1. そのセッションを開いている Claude Code のプロセスをすべて終了します。プロセスが動いている間は、そのプロセスが概要を持ち続け、また保存します。
2. ストアから、そのセッションの 1 件を消します ([概要の保存先](architecture.md#概要の保存先)を参照)。まず、ストアの全件をキーと目的の組で一覧し、目的の文からそのセッションのキーを探します。

   ```bash
   jq -r 'to_entries[] | "\(.key)\t\(.value.sections.purpose // "")"' ~/.claude/plugins/store/recap-plus_*.json
   ```

   キーは、`recap-plus:` にセッション ID を続けたものです。セッション ID は、`~/.claude/projects/` の下にあるそのセッションの transcript ファイルの名前から、`.jsonl` を除いたものです。見つけたキーを `key=` の行に貼り、すべてのストアからその 1 件を消します。

   ```bash
   key='<見つけたキー>'
   for f in ~/.claude/plugins/store/recap-plus_*.json; do
     jq --arg key "$key" 'del(.[$key])' "$f" > "$f.tmp" && mv "$f.tmp" "$f"
   done
   ```

   この 1 件を消すと、そのセッションの Haiku の呼び出し回数も 0 に戻ります。すべてのセッションを最初からにするには、ストアのファイルごと消します。
3. `claude --resume` でセッションを開き直します。mod が会話を読み直し、新しい概要を書きます。

## 使用量の確認

mod は自分の呼び出しを数えます。ストアのセッションごとの 1 件 ([概要の保存先](architecture.md#概要の保存先)を参照) に、そのセッションで Haiku を呼んだ回数と、その呼び出しで使った入力・出力トークンの累計を持ちます。トークン数は Claude Code が報告する値です。使える概要が返らなかった呼び出しも数えます。すべてのセッションの分を一覧するには、次のコマンドを使います。

```bash
jq -r 'to_entries[] | "\(.key)\t\(.value.usage.calls // 0)\t\(.value.usage.inputTokens // 0)\t\(.value.usage.outputTokens // 0)"' ~/.claude/plugins/store/recap-plus_*.json
```

各行は、キー、呼び出し回数、入力トークン、出力トークンの順です。mod が数え始める前に保存した 1 件は、0 から数えます。呼び出しは、同じ会話の次の概要と一緒にストアへ書き込みます。そのため、書き込む前に終了したプロセスの呼び出しは数えません。呼び出しはセッションと同じ扱いで課金されます。トークン数を金額にするには、[Anthropic の料金ページ](https://www.anthropic.com/pricing#api)にある Haiku の単価を使います。
